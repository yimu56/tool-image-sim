# 机台图片模拟器（imgsim）

一个 Windows 桌面小工具，用来**模拟生产机台持续产出图片**：按设定频率，把指定尺寸、指定文件大小的随机图片写入指定目录。适用于压测图片采集、落盘、上传、质检等链路，不需要真实相机或产线设备。

GUI 基于纯 Go 的原生控件（lxn/walk），编译结果是单个 exe，不需要 .NET、Java、gcc 或任何运行库。

---

## 快速开始

1. 双击 `dist/imgsim.exe`。
2. 填好尺寸、目标大小、生成间隔、输出目录，点「开始生成」，点「停止」结束。
3. 首次开始生成时会在 exe 同目录写出 `config.json`，下次启动自动回填上次参数。

默认输出位置是 exe 同目录下的 `output\yyyyMMdd\`。

---

## 界面参数

| 参数 | 说明 | 取值范围 |
|---|---|---|
| 宽度 / 高度 | 图片像素尺寸 | 8 ~ 16000 px |
| 目标大小 | **文件字节数**，不是"大约" | 1 ~ 204800 KB |
| 图片格式 | JPG / PNG / BMP | 默认 JPG |
| JPEG 质量 | 仅 JPG 生效，直接参与编码 | 1 ~ 100，默认 88 |
| 压不到目标时自动降质量 | 目标过小、细节降到最低仍超时，允许内部下调质量 | 默认开 |
| 严格填充到目标大小 | 用图片元数据把文件补齐到精确字节数 | 默认开 |
| 按日期建子目录 | 输出目录下再建 `yyyyMMdd` 子目录 | 默认开 |
| 生成间隔 | 两张图片之间的间隔 | 10 ~ 3600000 ms |
| 文件名前缀 | 会过滤 Windows 非法字符 | 如 `LINE-A` |
| 输出目录 | 可手填、「浏览...」选择、「打开」直接打开 | 任意可写目录 |

文件命名：`前缀_yyyyMMdd_HHmmss.mmm_000001.jpg`（毫秒时间戳 + 6 位递增序号）。

按钮：`开始生成` / `停止` / `清空日志`；右侧状态栏显示已生成张数、失败数、累计体积、单张耗时。

## 文件大小为什么能精确到字节

1. **档位自适应探测**：每测一个纹理档位都要全量渲染 + 编码一次，是整条链路最贵的操作。因此先测 0~110 档的中点，按实测体积决定「往下找 / 直接收工 / 往上找」，只在必要时才在对应区间二分。开启「严格填充」时，缺口小于目标 10% 就停止搜索、剩余交给填充；关闭填充时缺口小于 2.5% 才停，尽量让真实图像内容占满体积。
2. **质量二分**（可选）：若连最平滑的画面都超过目标，且勾选了「自动降质量」，JPEG 会自动下调质量再试。
3. **元数据填充**：剩余字节用合法的元数据块补齐 —— JPEG 用 `COM` 注释段（超过 65533 字节自动分段），PNG 用 `tEXt` 块，BMP 直接在像素数据后补零。解码器会忽略这些数据，**文件仍是完全合法、可正常打开的图片**。

所以 `ls` / 资源管理器里看到的大小严格等于 `目标大小 × 1024`。日志中的 `细节 x.xx` 是本次实际采用的纹理档位，`质量 xx` 是实际采用的 JPEG 质量。

> PNG/BMP 不使用质量参数。BMP 无压缩，大小由尺寸决定（宽 × 高 × 3 + 54 字节），此时目标大小仅在大于该值时有效。

### 质量与大小的取舍

- **大小优先**：保持「严格填充」+「自动降质量」开启，任何合理目标都能精确命中，代价是内部可能自动调低质量。
- **画质优先**：设定质量后取消「自动降质量」。若该质量下最小体积已超过目标，程序会输出可达到的最小文件并在日志明确提示「请调低质量、放大目标或勾选自动降质量」，**不会偷偷改掉你设的质量**。
- 目标大小低于该尺寸的编码下限时无法再压（例如 800×600 PNG 下限约 123 KB），日志会注明下限值。

## 日志

- **每张图片一行**，不丢行、不跳号。v1.0 曾为保护界面做过「前 20 条 + 每 20 条一条」的节流，看到 `[10]` 直接跳到 `[30]` 就是这个原因；v1.1 已彻底移除。
- 每行包含：序号、文件名、实际大小、耗时、细节档位、JPEG 质量、**内容指纹 `#xxxxxxxx`**、填充状态。指纹是整份文件 SHA-256 的前 4 字节，用来直观确认每帧画面确实不同。
- 为了在高频生成时也不卡界面：后台线程只做入队，UI 线程每 100 ms 批量追加一次；日志最多保留最近 500 行，超过后重建并保留最近 250 行。
- 「清空日志」立即丢弃历史与尚未刷新的日志，写入一行「日志已清空」，**不影响正在运行的任务和统计计数**。
- 单张耗时超过生成间隔时，日志会额外告警「实际频率会低于设定值」。

## 会不会生成一模一样的图片？

**不会。** 每帧随机种子由 `纳秒时间戳 XOR (递增序号 × 黄金比例常数)` 生成，同时驱动两层随机斑块网格和逐像素噪声。即使细节档位、质量、目标大小完全相同，每一帧的画面内容也不同；填充用的元数据虽然固定，但前面的图像数据不同，整份文件的哈希依旧不同。

`features_test.go` 中的 `TestFramesAreNeverIdentical` 连续模拟 12 帧（细节档位打满、带精确填充），同时比对**原始像素 SHA-256** 与**最终文件 SHA-256**，要求两两唯一；`TestSeedDeterminism` 另外验证「相同种子可复现」，便于问题定位。

文件名带毫秒时间戳 + 递增序号，同一进程内序号不重置，启停多次也不会互相覆盖。

## 命令行参数

| 参数 | 说明 |
|---|---|
| `-config <路径>` | 指定配置文件，默认 exe 同目录 `config.json` |
| `-autostart` | 启动后立即开始生成（无人值守场景） |
| `-once` | 只生成一张图片后退出，向终端打印实际大小（自检用，需从命令行运行） |

`config.json` 字段：`width`、`height`、`target_kb`、`format`、`pad_to_target`、`quality`、`auto_quality`、`interval_ms`、`prefix`、`out_dir`、`date_subdir`。

## 从源码构建

环境：Windows + Go 1.21 或更高版本，**不需要 gcc / CGO**。

双击 `build.bat`，或手动执行：

```bat
go mod tidy
go build -trimpath -ldflags="-H windowsgui -s -w" -o dist\imgsim.exe .
```

`app.manifest` 与 `rsrc.syso` 提供现代控件外观和 DPI 感知，已随源码提供。若要重新生成 `rsrc.syso`：

```bat
go install github.com/akavel/rsrc@latest
rsrc -manifest app.manifest -arch amd64 -o rsrc.syso
```

国内网络建议设置 `GOPROXY=https://goproxy.cn,direct`。

## 运行测试

```bat
go vet ./...
go test ./...
go test -run=^$ -bench=. -benchmem ./...
```

测试覆盖：精确大小与可解码性、BMP 固定大小、质量参数与自动降质量开关、日志不丢行 / 截断 / 清空、连续 12 帧唯一性、文件名清洗。

基准覆盖：默认 1280×960 / 800KB、小图 + 大目标（主要靠填充）、需要收敛的二分场景，以及渲染与 JPEG 编码的单独耗时。

## 性能

探测次数优化后（Intel Core Ultra 5 125H / Go 1.26.5，同进程对比取 4 轮最小值）：

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 默认 1280×960 / 800KB JPG | 185 ms | **55 ms** |
| 320×240 / 512KB JPG（主要靠填充） | 28 ms | **8 ms** |
| 单张分配内存（默认场景） | 18.8 MB | 6.9 MB |

主要措施：中点档位一次探测即可收工、精确填充时 10% 容差提前结束、最平滑画面在质量二分里只渲染一次、噪声插值权重预计算成表、编码缓冲一次开够。大小核调度与温度会让绝对值有波动，对比请以同机同轮基准为准。

## 目录结构

```
imgsim/
  main.go            GUI、配置读写、日志刷新
  generator.go       图片生成、体积逼近、JPEG/PNG/BMP 编码与元数据填充
  worker.go          定时调度、落盘命名、统计与日志、种子生成
  config.go          config.json 读写与默认值
  logbuffer.go       线程安全的日志缓冲（可批量刷新、可截断、可清空）
  *_test.go          单元测试
  *_bench_test.go    生成链路基准测试
  app.manifest       Windows 清单（Common Controls 6 + DPI 感知）
  rsrc.syso          由清单编译出的资源对象
  build.bat          一键构建脚本
  dist/imgsim.exe    可直接运行的成品
```

## 已知限制

1. 单张耗时随尺寸增长（1280×960 JPG 约 55~80 ms，视 CPU 而定）；间隔设得比耗时更短时实际频率会低于设定值，日志会告警。
2. 目标大小低于编码下限时无法精确命中，日志会说明下限值。
3. BMP 无压缩，大小由尺寸锁定。
4. 生成的是合成纹理（随机斑块 + 传感器噪声），用于链路压测，不是真实工件照片。
